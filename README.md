# dsh-codex-setting-ui

一个为 DeepSeek Harness 设置窗口整理布局的独立插件：左侧分类导航，右侧继续使用 Harness 原有设置表单。设置布局模块不读写 Harness 设置值。0.2.0 新增默认关闭的实验性消息编辑模块，不自动安装其他插件。

## 功能

- 将设置分类分组显示，并提供分类搜索。
- 支持浅色、深色和窄窗口布局，键盘焦点清晰可见。
- 沿用 Harness 原有表单、保存行为、关闭与 Escape 操作。
- 分类动态增删时同步导航；停用插件时恢复原导航和样式。
- 搜索只匹配分类名称和分类 ID，不搜索设置内容或密钥。

## 消息编辑（实验，默认关闭）

安装或升级后，在设置窗口左侧导航底部勾选 **消息编辑（实验）**。开关仅保存于当前客户端的插件本地存储，不写入 Harness 配置；关闭开关立即移除编辑控件，不影响设置布局。

开启后，仅最新一条普通用户消息旁出现编辑按钮。可直接重发原文，也可修改原文、取消，或使用“重新发送”/ Ctrl/Cmd + Enter 提交。插件通过宿主接口从原消息入队之前的真实历史边界创建新会话分支，再发送修改后的文本并打开新会话；原问题及其后续回复不会进入新分支。原会话保留。提交时会读取当前对话框选中的模型（含思考强度），先应用到新分支再发送；不再使用历史位置继承的旧模型。切换仍在进行或应用失败时不会发送。网络失败重试固定使用首次提交的模型与请求标识，避免改变已受理请求的语义。

**这不是同一会话内覆盖消息，也尚未完全复刻 Codex 的编辑体验。** 首版只支持已结束轮次的纯文本消息；附件、中途追加、上一轮回复期间排队发送、存在待发送队列或历史边界未加载时禁用编辑。缺少历史时可先向上滚动加载。分支不会撤销工具已经写入的文件或外部操作。

发送失败保留编辑内容，并复用已创建的分支和发送标识；分支创建后为保证重试幂等会锁定草稿，可取消后重新编辑。消息已发送但导航失败时仅重试打开新会话，不再发送。

消息编辑使用可选的宿主服务注入：服务不存在时开关禁用，设置布局仍可工作。按钮定位依赖当前版本的 `data-chat-flow-kind`、`data-chat-node-key` 标记；官方升级后可能需要适配。整个插件不修改官方 App、官方插件包或生成 bundle，停用后恢复官方界面。

若之前安装了独立的 `dsh-message-edit` 候选插件，请先停用它，再启用本仓库的消息编辑模块，避免出现两套编辑控件。

## 安装

先克隆仓库：

```sh
git clone https://github.com/zwqjoy/dsh-codex-setting-ui.git
```

在 DeepSeek Harness 中打开“插件 → 添加插件 → 安装第三方插件”，把“包名或地址”设为克隆后包含 `package.json` 的 `dsh-codex-setting-ui` 目录，然后按应用提示重启。

也可以下载源码 ZIP 并解压，再选择其中包含 `package.json` 的插件目录。不要把 ZIP 文件本身填入地址；如果使用本地目录链接安装，请保留目录。

桌面版 profile 由 Harness 应用管理，请从应用的插件页面安装。此插件的发布包是本地目录插件；README 不承诺 npm 或 CLI 安装方式。

卸载或停用插件即可恢复原设置布局。设置值不会被插件迁移或删除。

## 兼容性

此插件按 DeepSeek Harness **0.2.1-rc.2** 的设置窗口结构实现，依赖 `[data-shortcut-modal="settings"][role="dialog"]` 和 `settings.section` 分类登记接口。遇到无法识别的窗口结构时，插件不会改动界面。

插件通过原有导航按钮切换分类，不替换设置表单，也不维护第二份设置状态。设置布局样式仅作用于识别到的设置窗口；消息编辑默认关闭，开启时才在最新用户消息旁添加控件。替换整个设置窗口的主题可能与本插件不兼容；Harness 更新后也可能需要适配。

0.2.2 已在真实 Harness App 验证安装、原文直接重发、分支创建，以及实际请求使用当前选中的模型。该次模型服务返回 HTTP 502，未获得成功回复；详见 VALIDATION.md。目前不能保证所有 Harness 版本和第三方主题均兼容。

## 开发与验证

源码位于 `src/`，`scripts/build.mjs` 使用 Node 内置模块生成 `lib/client.js`。

```sh
npm run check
npm pack
```

浏览器检查页使用发布 bundle 和模拟的宿主设置表单，不会连接或修改真实设置：

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

然后打开 `http://127.0.0.1:8765/test/browser.html` 并运行检查。
